# Week 02 — Engineering log

The protocol decision I am most likely to revisit in Week 4 is requiring contiguous sequence numbers within each WebSocket connection. Every robot starts at sequence 1 with HELLO. The gateway issues a fresh session ID in WELCOME and starts its own sequence at 1. A lower robot sequence is a duplicate. A higher sequence is a gap. The gateway rejects both frames and returns the next expected value. This makes the contract testable today, especially when malformed telemetry is followed by a corrected sample using the same sequence.

The uncomfortable case is a command sent just before a connection drops. A transport sequence number describes a frame within a single connection. A reconnect gets a new session and starts counting again, so it cannot explain whether the robot acted on a command from the previous session. Carrying the same sequence across connections would then force our session protocol to preserve every frame, including expendable telemetry. It would also make a reset or crash ambiguous to both sides. I kept connection sequence numbers for ordering and used a separate command UUID in COMMAND, COMMAND_ACK, and COMMAND_RESULT. Week 4 can reconcile command outcomes by UUID even after the transport changes.

The design also keeps robot send time and gateway receive time in the telemetry view. The WELCOME timestamp gives the robot an initial skew estimate. The gateway orders messages by sequence and exposes the receive timestamp so an operator can assess when the last sample reached the service. Command expiry will need a clock policy of its own, especially after reconnection.

I checked the contract with scripted WebSocket sessions, an independent client reading the worked example, and a test peer that sends the simulator MOVE_TO, STOP, and DOCK. The REST command endpoint validates requests and returns a documented 501 for known robots. The next resilience milestone will use the simulator to distinguish a transport close from a silent link and to measure when the gateway should stop treating data as current. I will carry the command UUID independently of session state when delivery and reconciliation are introduced.
